# Dr. Ferjoo 规则遍历、证据库与诊断体系改进报告

版本：v0.2 研究与工程基线
基于仓库：`hxh2002/Ferjoo`，公开主分支原始提交 `75e342f`
检索截止：2026-08-28
项目目标：让每一次发酵，都有迹可循。

## 1. 交付结论

本轮已把项目从“两份会漂移的规则脚本 + 无法重复的自检说明”，推进到以下可运行基线：

1. 浏览器和 Node 共用一个规则实现；
2. 2,016 个核心组合可以确定顺序全量遍历，全部输出经过结构与证据契约校验；
3. 当前 2,016 个结果压缩为 56 个逐字叙事等价类；
4. UI 的约 12.89 亿机械组合不再直接暴力相乘，而压缩为 614 条有优先级的语义审阅队列；
5. 食品安全和发酵机理证据子库共建立 27 张详细证据卡；
6. 诊断结果现在返回命中规则、证据键、完整引用、估时适用性和 pH 辅助分层；
7. 已修复时间空值、污染优先、高温线性外推、pH 旁路冲突、自然语言污染漏检和阶段覆盖吞并等关键问题；
8. 已建立 Draft 2020-12 JSON Schema，定义来源到最终输出的完整引用链。

这不是“所有场景已经获得实验室级真值”的终点。`reports/review-queue.json` 中的 614 条记录仍明确标记了 `核验 → 检索 → 重写` 状态；本轮完成了结构遍历、证据初建、P0/P1 规则修复和代表场景重写，尚未假装把品牌经验时间窗变成了学术定律。

## 2. 项目现状审计

公开仓库当前只有根目录静态应用，没有中断记录所说的 `knowledge/` 子项目、服务器或包管理配置。README 原先声称存在 `source/`，公开提交中同样不存在。因此本轮只对可复现的公开文件下结论，不推测未提交知识库的内容。

### 2.1 原始输入空间

| 轴 | 数量 | 原始值类型 |
|---|---:|---|
| 阶段 | 6 | 起种初期、活跃、稳定、复活、冷藏、成熟 |
| 比例/种型 | 6 | 1:1:1 至深度重置，另含硬种 |
| 高度/状态 | 8 | 无变化至回落，另含液体层 |
| 温度区间 | 7 | `<15℃` 至 `>32℃` |
| 核心笛卡尔积 | 2,016 | `6 × 6 × 8 × 7` |

UI 还含温度整数、0–48 小时、颜色、气味和 pH。若把离散控件机械相乘，约为 1,288,627,200 组，备注与自然语言仍是无限空间。这一数字不能作为人工审阅任务直接执行，因为多数维度在当前规则中被高优先级覆盖、仅在阈值边界变化，或根本不改变核心诊断。

### 2.2 原始 P0 缺陷

| 缺陷 | 原始影响 | 当前处理 |
|---|---|---|
| Node / 浏览器双规则源 | 同一输入严重度可不同 | Node 改为浏览器 UMD 规则的薄兼容入口 |
| `elapsedHours: null` 被当作 0 | 成熟种 `none/slight` 的 84 组被误判为“刚观察” | 显式区分 unknown、0、窗口前、窗口内、窗口后 |
| 未选高度先阻断污染结果 | 粉红/霉变也先被要求补高度 | 先运行污染安全规则；污染成立直接显示弃用 |
| 自然语言不抽取污染 | 文本中的粉红/霉变被漏掉 | 抽取明确颜色/气味污染信号，并增加否定识别 |
| `>32℃` 使用系数 0.5 | 高温继续被解释为“更快” | 高温段 `coef=null`，停止线性估时并建议降温重计 |
| pH 只在 `app.js` 旁路显示 | 可与污染结果同时显示绿色卡片 | pH 移入统一结果；污染时明确不能推翻弃用 |
| 阶段覆盖过粗 | 活跃期 hooch/回落/3 倍以上都判“正常” | 对活跃、稳定、复活、冷藏分别保留过峰、液层和时点歧义 |
| 固定时间表伪装成科学常数 | 输出没有证据角色和适用边界 | 标为 `brand-experience-needs-calibration` |

## 3. 证据库

### 3.1 检索方法

本轮按“结构化快速综述”执行，不冒充穷尽性系统综述：

- 渠道包括政府/监管机构、大学 Extension、PubMed/PMC、出版社 DOI 页、ASM、eLife、PeerJ、J-STAGE 和机构库；
- 排除没有方法与研究对象的食谱博客、社交媒体经验值和固定“最佳小时数”；
- 各主题至少获得一项直接原始研究；关键高温结论要求单菌/共培养机制与连续回接真实酵种交叉支持；
- 保留对象、面粉、含水量、温度、接种量和终点不同造成的冲突，不用多数票抹平；
- 证据缺口转为二次检索或项目实验，不被误写成“不可能场景”。

### 3.2 证据卡规模

| 子库 | 数量 | 主要覆盖 |
|---|---:|---|
| 食品安全 | 16 | 霉菌/异常色、深色 hooch、腐败气味、pH 屏障、生面粉、特殊配方边界 |
| 发酵机理 | 11 | 温度、时间、接种比例、pH/TTA、群落演替、产气/留气、峰值/过峰 |
| 合计 | 27 | 每条含完整引文、DOI/URL、证据类型、主要结果、适用边界和规则映射 |

最重要的证据修正包括：

- 可见有色或绒毛状霉变应整份丢弃；深色、可流动、无绒毛的酒精液层需要与黑色点/膜/菌落分开；
- pH 4.6 只能表达酸化屏障，不能表达“已灭菌”或生食许可；
- 生面粉、生酵种和生面团不应品尝，充分烘烤是独立控制点；
- 代表性研究中酸面团酵母的温度最适约在 27–28℃，35℃可出现抑制；乳酸菌和酵母的响应在高温段分叉，因此 `>32℃ → 时间减半` 不成立；
- 单次膨胀倍数不能精确识别峰值，日龄也不能独立证明成熟；需要完整曲线和重复周期；
- 相同可见输入仍可能因面粉、含水、群落、维护历史和留气能力不同而产生不同结果。

### 3.3 证据角色

运行时引用明确区分：

- `primary-research`：原始同行评议研究；
- `peer-reviewed-review`：综述；
- `regulatory-guidance` / `official-extension-guidance`：监管或大学安全指导；
- `brand-experience-needs-calibration`：项目经验先验，不能伪装为通用学术阈值。

## 4. 引用体系

`research/citation-system.md` 和 `research/schemas/citation-bundle.schema.json` 定义了十类记录：

```text
来源 → 证据摘录 → 原子观点 → 规则版本 → 输出模板 → 场景 → 诊断输出
                 ↘ 冲突 / 二次检索 / 审校 / 审计事件 ↗
```

每个来源可记录出版状态、更正、撤回、网页内容哈希与元数据来源；每个观点区分 `direct / inferred / experience`；规则保存适用范围、不确定性政策和安全审校门槛；最终输出按句连接模板、观点与证据，而不是只在报告末尾放一串链接。

Schema 使用 JSON Schema 2020-12，含 39 个 `$defs`、74 个本地 `$ref`，JSON 语法和本地引用均已校验。

## 5. 组合归并与遍历策略

### 5.1 不把“少见”当作“不可能”

当前四轴输入本身很难证明物理不可能。例如“冷藏期 + 翻倍”可能指入冰箱前、冷藏中或回温后的观测；“很早就回落”可能来自个体高活性，也可能是时点/阶段填错。此类场景应要求澄清，而不是剪掉。

每条场景保留四个正交标签：

- `validity`：有效、缺必填、数值无效、超出领域；
- `consistency`：一致、需澄清、超出校准模型；
- `plausibility`：常见、少见但可能、未知证据缺口；
- `dominance`：无覆盖、安全覆盖、阶段覆盖、修饰项。

### 5.2 三层等价

1. 引擎等价：命中同一规则路径；
2. 诊断等价：状态、严重度、原因、动作和安全文字相同；
3. 审阅等价：证据角色、适用性、需核验观点与重写目标相同。

“当前输出相同”只能证明实现等价，不能自动证明领域等价。

### 5.3 遍历顺序

1. 污染与食品安全硬停止；
2. 无效和缺失输入；
3. 需要澄清的时点/维度冲突；
4. 时间、温度和 pH 阈值边界；
5. 当前 56 个叙事等价类代表项；
6. 变形测试与否定表达；
7. 全部 2,016 个核心原始组合作结构回归。

这使安全缺陷最先暴露，也避免把计算资源花在被污染规则完全覆盖的比例/高度变化上。

## 7. 已实现的“核验—检索—重写”

### 核验

- 统一 Node / 浏览器规则源；
- 修复空时间与安全优先；
- 对全部 2,016 个核心组合校验 API 契约、非空原因/动作、严重度、输入回显、规则追踪和证据追踪；
- 对时间、污染、pH、高温、否定表达和阶段语义建立专项回归测试。

### 检索

- 建立 27 张详细证据卡；
- 把高温、pH、生食、霉菌、hooch、成熟、峰值和比例固定时间等核心观点映射到证据或明确的证据缺口；
- 对缺少直接外部支持的固定小时表统一标记为品牌经验待校准。

### 重写

- “未知时间”重写为信息不足，不再虚构完整观察窗口；
- 时间窗口前/内/后使用不同状态和动作；
- 高温重写为停止估时、降温后重计；
- pH 重写为辅助酸化信息；污染时 pH 不改变弃用；
- 起种活跃/稳定、复活和冷藏分别保留液层、过峰、大幅上升和时点歧义；
- 所有格式化建议附证据或品牌经验键。

## 9. 不能在本轮假装完成的事项

1. 固定比例时间表没有项目用户的真实曲线校准；目前仍只是保守展示的品牌经验先验。
2. 当前轴把 `1:2:1 硬种` 混入喂养比例，又把 `hooch` 混入高度；下一版应拆成接种比例、水合度、曲线位置和表面状态。
3. 仅凭高度倍数不能精确识别峰值；应增加顶部形态、历史最大高度、是否已经回落和时间序列。
4. 自然语言否定识别只覆盖明确短语，不是通用中文语义模型；结构化安全输入仍应优先。
5. 没有图像污染分类、真实设备 DOM/视觉回归或食品微生物实验室验证。
6. 614 条队列尚未全部由两名领域审校者逐条签署；安全硬规则仍建议至少一名食品微生物/食品安全人员复核。
